## 入口

用户要看某条内容或某个账号的评论区时用。先确认平台、样本范围和时间窗口。

## 步骤

1. 用 `phone_launch_app` 打开平台，`phone_observe` 看评论列表，`phone_scroll` 采样至少 20–50 条；样本不足就说明。
2. 只记录公开可见的评论，去掉用户名、头像、手机号等个人信息。
3. 按四类归纳：在问什么、误解什么、最认同什么、反对什么；每类保留 2–3 条代表性原句（脱敏）。
4. 把高频问题转成选题，写清读者原话、内容角度和需要提供的证据。
5. 评论里的功能请求和投诉单列，不混进内容选题。
6. 输出结论时写样本量和局限，例如「采样 32 条，不能代表全部评论」。

## 容易出错的地方

- 把点赞最高的几条当全部民意。
- 原样搬运他人评论和昵称。
- 把提问当需求，直接承诺产品功能。
- 只找支持自己观点的评论。

## 怎样算办成(核实证据)

每个结论能追到脱敏样本；给出样本量；至少产出 3 个有原话依据的选题。

## 什么时候停下交给用户

需要登录、验证码或读取私信时停；涉及未成年人、医疗隐私或人身攻击时不做二次传播。
