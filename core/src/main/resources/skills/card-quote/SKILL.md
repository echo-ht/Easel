## 入口

先读 `card-design` 设计系统，选风格、锁配色，再决定是金句卡还是数据卡。金句卡靠排版层级，避免渐变文字、粗黑大标题和“居中一切”。

## 画幅

- 16:9 横版：CSS 1600x900，`render_card` 用 `width=1600`、`height=900`、`scale=2`。
- 需要更高的信息密度时仍保持 16:9，不要临时改成 3:4；竖版知识卡交给其他卡片技能。

## 骨架 A：金句卡

- 顶部：小标签（如 INSIGHT、观点、Quote）和品牌名或栏目名。
- 中部：一句 hero 金句，2-3 行，最戳的词用一个强调色；字号大、字重轻。
- 金句下：出处、作者或来源，没有真实署名就用来源或品牌名，不硬塞头像。
- 底部：品牌水印、日期或一条细线。
- 背景可以有极淡网格或纸纹，但不要玻璃拟态、装饰 blob 和渐变文字。

## 骨架 B：数据卡

- 一个主数字超大，占视觉中心；单位和小说明紧挨着它。
- 2-4 个副指标横向排开，每个是大数字加一行标签，对齐到同一网格。
- 底部加一句结论或来源脚注，如“数据来源 · 截至某日”，建立可信度。
- 数字用 `monospace` 或干净的 `sans-serif`，不用 emoji 当图标。

## 手机端写法

- HTML 必须自包含：内联 CSS、系统字体、内联 SVG、`data:` 图片。
- 不用 Tailwind、Google Fonts、外部图片、脚本或 iframe。
- 容器直接写固定 CSS 尺寸，不要在页面里用响应式缩放；清晰度交给 `scale`。
- 先用 `/workspace/cards/` 之类的子目录放 HTML 和 PNG，再调用 `render_card`。

## 渲染与交付

1. 写 `/workspace/cards/<主题>.html`。
2. 调用 `render_card`，例如 `htmlPath=/workspace/cards/quote.html`、`outPath=/workspace/cards/quote.png`、`width=1600`、`height=900`、`scale=2`。
3. 读返回的 `audit`。`pass` 为 false 时按 `problems` 调整：补内容、加结构、改间距或换骨架，再渲染到新的 PNG。
4. 全通过后再用 `share_file` 交付；不要把失败版本说成成品。

## 与其他卡片技能的区别

- 本技能是 16:9 横版金句或数据卡，适合微博、知乎、公众号和 X。
- 1080x1440 竖版知识卡用竖版卡片技能。
- 1080x1920 竖版营销海报用海报技能。
