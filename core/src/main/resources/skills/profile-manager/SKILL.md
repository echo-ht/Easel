## 入口

用户要改画像，或一次复盘产生了可复用经验时用。先读当前画像，不要覆盖未确认的内容。

## 步骤

1. 完整读当前画像，列出本次要改的字段和理由。
2. 只改有证据的部分：用户明确偏好、连续多次有效的内容规律、已验证的红线。
3. 新信息和旧画像冲突时并列展示，让用户决定；不要静默删掉旧内容。
4. 更新后保留「长期记忆」里的日期和来源，例如「2026-11 复盘：收藏型清单表现稳定」。
5. 一次性改动超过三处时先给 diff 摘要，用户确认后再保存。
6. 保存后回读，确认六部分仍然完整、没有重复段落。

## 容易出错的地方

- 把单条爆款当长期规律。
- 画像越改越长，核心定位被淹没。
- 用模型推测替换用户原话。
- 删除红线却没有记录。

## 怎样算办成(核实证据)

每处变更都有来源或理由；冲突有用户决定；保存后的画像可读、无重复、核心定位仍清楚。

## 什么时候停下交给用户

涉及定位、受众或红线变更时必须确认；证据不足时只记录候选，不写进正式画像。
